## Orient yourself first

**Seraph Mesh is not a pretrained biological neural network.** The neuron/dendrite/synapse language is an explanatory analogy for distributed software roles. It does not mean Seraph contains proprietary model weights, biological neurons, a proven artificial consciousness, or one independently qualified, fully integrated software brain.

For the vocabulary see the [neuroscience analogy glossary](NEURAL_ANALOGY_GLOSSARY.md).

The concepts in this library have **mixed maturity**:
- **General engineering patterns:** durable project records, human permission boundaries, task tracking, independent test evidence, source provenance and restart-aware recovery.
- **Seraph development history:** documented prototypes and bounded tests. Their existence does not mean every subsystem is deployed or qualified together.
- **Research and long-term aspirations:** autonomous coordination, broadly reliable cross-provider recovery and advanced governance. These are not proven simply by documentation.
- **Public software status:** The [Age of Free Programming](../../README.md) primarily distributes educational prompts and instructions; it does **not** include the protected private Seraph Core implementation or a qualified production deployment.

## What this library does NOT expose

It intentionally contains **no private source code, exact runtime graph, unpublished schemas or algorithms, production security configuration, protected authority-enforcement internals, live endpoints, hostnames, account records, payment information, family information, private research records or operational vulnerabilities**.

A public description of what a component is *for* is not a grant of access to the private system or permission to reproduce original protected implementation. Do not import private Seraph files or real personal data into educational projects.

**Security note:** An AI allowed to run real terminal commands can affect files outside a conversational promise or an advisory allowed-folder setting. Use a separate low-privilege test account, VM, or appropriately restricted container when experimenting. Never treat a model-generated success report as a verified test receipt.
