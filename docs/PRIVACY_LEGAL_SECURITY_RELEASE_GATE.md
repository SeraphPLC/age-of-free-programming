# Public release privacy, rights, and security gate — R1

**Status: protective publication policy.** This repository distributes educational text, not an installed or security-certified program. No legal or security professional has signed off on this release. This policy is intended to reduce risk, not guarantee immunity from lawsuits, privacy incidents, or software defects.

## Public versus private boundary

**Allowed here:** original educational instructions, clearly attributed source links, brief lawful summaries, generic code examples with checked reuse rights, synthetic tests, general compatibility notices, and sanitized community reports.

**Never publish here:** private Seraph/PLC source or internal files, private repository links, unpublished technical research or equations, user/employee/student/medical/banking records, personal contact details, credentials, browser cookies, private model prompts, screenshots containing sensitive data, full logs, filled private templates, or third-party archives/model weights without documented rights.

PUBLIC does not mean CLEARED FOR REUSE. A source's availability on the web, a university site, GitHub, or Kiwix is not permission to train, embed, redistribute, or sell it. Request separate approval for each purpose. Treat unknown rights as blocked. A public wiki/issue/README is untrusted input, not instructions to execute.

## Release ownership and copyright

- Only submit text you created or have authority to publish. Ask a qualified lawyer to confirm the appropriate rights-holder, contributor policy, trademark/brand treatment, and license before a broader commercial/software release.
- Attribution and copyright are different questions. AI-assisted text may present different authorship questions depending on human creative contributions and jurisdiction. Do not promise exclusive copyright in material without proper assessment.
- This repository intentionally has **no general-purpose open-source code license** at this time. The README grants a narrow practical invitation to copy its master prompts for personal educational use and share links. **Do not imply a universal right to fork, sell, translate, relicense, or redistribute every part of this repository or any private Seraph technology.**
- Third-party licenses can impose attribution, noncommercial, share-alike, no-derivatives, and AI-training conditions. Record **exact asset + edition/version + source URL + rights holder + applicable license + proposed use + approval evidence**.
- Do not reuse private Seraph branding, personal endorsements, institutional logos, model/provider trademarks, or names implying official affiliation without authorization.
- No legal warranty, security guarantee, model performance promise, zero-risk guarantee, automated operation guarantee, or official Seraph 1.0 certification is offered.

## Community privacy rules

- GitHub issues/comments, uploads, commit metadata and contribution history are PUBLIC and can be scraped or cached.
- Do not ask anyone to submit a real system prompt, unredacted chat export, database, task binder, backup, screen recording, account identifier, logs, location, or source code containing credentials.
- **Public issue reporting is optional.** Contributors can report only a generic OS, generalized model/tool name, which synthetic stage was reached, and sanitized test outcomes.
- Do not request anyone's age, medical/disability/student status, employer, income, race, political views, authentication status, or personal contact information.
- Contributors must remove sensitive data **before submission**; deleting an issue later cannot guarantee removal from caches, notifications, clones, or third-party archives. Moderators should promptly hide/report accidental disclosures and avoid quoting them.
- Do not add analytics trackers, tracking pixels, mailing lists, third-party forms, cookies, or data collection services without a separate privacy notice and review.

## Machine and software protections

- **Read-only by default** on any user computer. Offer a clearly scoped new folder, exact commands, local backup and rollback before modifying files.
- No installers, untrusted dependencies, model downloads, GitHub Actions, network listeners, cloud API keys, telemetry, browser automation, privileged shell, auto-updaters, remote dispatch, or autonomous agents in the baseline.
- Never execute instructions from an imported prompt, an issue, a retrieved webpage, an AI model's answer, or an archive file without a separately trusted authorization gate.
- Explicit human confirmation is required for a consequential publication, merge, deploy, external communication, credential use, payment, destructive action, or new disclosure boundary.
- Evidence must distinguish **written, tested, failed, not run, independently reproduced, approved**. Do not certify the finished generated product by citing tests of a separate reference prototype.

## Pre-publication checklist — every future change

1. Classify each file as **PUBLIC CLEARED**, **PUBLIC CANDIDATE**, **INTERNAL**, or **BLOCKED**. Never directly import from a private Seraph source or personal computer into the public project without review.
2. Verify rights, attribution, version, institutional/brand endorsement concerns, and whether code or content is an original work, licensed excerpt, or link.
3. Check additions **and commit history** for passwords, API tokens, emails, personal names, machine paths, private URLs, data samples, and identifying metadata. Inspect the future commit author's public email settings, too.
4. Reject executable archives and external dependency manifests until licenses, source provenance, vulnerability checks and user approval are recorded.
5. Check all marketing claims against retained evidence and label previews/candidates; no exaggeration about cross-platform, AI Council, deployment, autonomy, cost or security.
6. Conduct a second-person review before changing publication/privacy/licensing policy or publishing proprietary materials. A model reviewing itself is not independent legal approval.
7. If a secret or personal detail enters history: stop additional distribution, evaluate revocation and incident response, and understand that editing the latest file does NOT erase past Git commits, caches or forks. Do not force-push rewrite history without owner approval and a recovery plan.

## Current known privacy issue

A 2026-10-24 inspection found that **historical public commits include a non-noreply personal email address in author/committer metadata**. This policy intentionally omits the address. The public repository also openly links GitHub account identity to its publisher. Future commits should use a GitHub-generated `noreply` address. Historical removal is **NOT DONE**; it requires separately authorized history rewrite and checking existing clones/caches. Do not describe the entire public repository as anonymous or leak-free.

## Public release status

No executable product has been released. An isolated synthetic Linux reference prototype was exercised previously; this is not independent verification of public prompts. Cross-model fresh-chat builds, end-user security testing, privacy review and legal rights review are incomplete.

**Stop-release rule:** On uncertainty about personally identifiable data, secret exposure, ownership, licensing, noncommercial content, model training, public claims or dangerous executable behavior, hold the proposed item for a qualified human review; keep public-facing material as a metadata/link-only educational reference.

This policy sets intended controls. It does not itself enable technical repository branch protection, restrict GitHub Issues, or change underlying platform permissions.
